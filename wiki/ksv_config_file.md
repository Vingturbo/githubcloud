# KSV 配置文件

> 关于对于本软件的值的规范，请参考[参数与开关传递规范](options_and_arguments)  
> 下列阐述如无特殊说明，仅对于这个标准而言

## 简述

KSV 配置文件，全称 Key Space Value ，是一种易于程序解析和处理的扁平化键值对纯文本配置文件，以固定长度的键和任意长度的，不带有换行符的值组成，同时支持注释
> 关于结构化配置文件，请查看[CDS 配置文件](cds_config_file)

## 规范

- 0: 键  
KSV 配置文件的键，均为32字节长度的、不带前导字符的、全小写的HEX字符串，即类似于 `91de27d37ac04464d4f8fd53afd0c2bc` 的键都是合法的，这十分易于程序解析，但是注定代表了不是人类易于阅读的

- 1: 值  
KSV 配置文件支持不带有换行符的任意字符串值，这代表着类似于 `hello world`, `I use Arch btw.`, `program` 等值都是合法形式

- 2: 注释  
KSV 配置文件仅支持以`#`开头的单行注释，所以，类似于 `#hello world`, `# hello program`, `#token api` 等注释都是合法的，程序解析时会直接跳过，而像 `‌ #Windows is best`, `//#help me`, `＃你的胆子真是肥嘟嘟的` 等，都属于非法注释，可能会导致键值对解析错误



- 3: 总述  
对于合法的 KSV 配置文件的任意一行，都只有三种可能  
    - 仅包含一个换行符的空行  
    - 注释  
    - 合法的键值对

    其中，正常的键值对是键与值中间加入一个空格来拼接的，而由于 KSV 配置文件按照换行符 (\n, LF) 来区分每一个键值对，故而一个合法的值不能包含换行符，而一个合法的键值对，则类似于 `e877952a5e5b66ad93b3901e570bafa0 B友，你要点赞，你要投币啊，B友，你这个B……站用户，你要幸福啊，B友！`  
所以一个合格的 KSV 配置文件类似于如下所示

``` KSV
#example KSV config file

bdc0bfa3088d5feedc1588c7807f05ec @@please_change_this_password
e1d357e4802e1c961acc37482dcc5e10 @@./
e877952a5e5b66ad93b3901e570bafa0 B友，你要点赞，你要投币啊，B友，你这个B……站用户，你要幸福啊，B友！

#i18n

1d510a311320bb3fb97abff44530c9d9 @@出现不受到支持的开关
8a94c5bae8543a47fb0b5dcdc86240e4 @@警告: 在没有开启高级参数的情况下，仍然出现了不是字面量的参数值
4ce3b19939d8cec5e725f8696a45e663 @@出现互相冲突或者不存在的开关
eddeb0cca6c84cffa12b5a7fb2900055 @@参数数量不匹配
4efd85ff4db9a53546080c184278e100 @@缺失必须的开关类
361aa96dff5d304d40317e2251140951 @@缺失必须的主开关
```

## 程序使用  
- a) 从输入读取配置文件的文本内容
- b) 从文件第一个字节开始，按照`\n`切分为字符串数组
- c) 从第0个数组项开始，重复，依次递增，将获取的字符串按照 c0 到 c2 处理，直到达到数组长度
    - c0) 判断第一个字符是否为 `'#'` 或 `'\n'`（即空行），如果是，跳过这个数组项
    - c1) 通过字符串切分得到 `[0, 31]` 的字符串，这是键，然后切分得到 `[33, ]` 的字符串，这是值
    - c2) 将值以键为索引，加入存储的数据结构中，对于 `c++` ，我们建议使用 `STL的map容器` ，对于 `Python` 我们建议使用字典，总而言之，我们建议使用索引唯一对应值的数据结构类型

## 特殊说明

- 对于键 `00000000000000000000000000000000` 和 `ffffffffffffffffffffffffffffffff` 我们通常将其视为特殊值，当然，你可以可以正常解析使用，这是一个 UB(未定义行为) 你可以根据使用场景自由选择

- 关于键的产生，我们的做法是，使用MD5哈希算法根据意义生成不重复的键，命令是(以 Linux 为准) `echo -n "$THINK" | md5sum | cut -d' ' -f1`

- 我们建议将 KSV 配置文件的文件扩展名设置为 `.ksv`

## 特殊情况处理

- 如果在处理前后出现两个相同的键，但是对应着不同的值，默认后面的值覆盖前面的值
